JWT Decoder

JWT를 붙여넣으면 Header와 Payload를 풀어 보여 주고 exp·iat·nbf를 날짜로 바꿔 만료 여부를 알려 줍니다. 비밀키나 공개키를 넣으면 서명도 검증합니다.

브라우저에서만 처리 무료 · 회원가입 없음

사용 방법

          
    
            
  1. JWT를 붙여넣으면 바로 Header와 Payload를 풀어서 보여 줍니다. Bearer  접두어가 붙어 있어도 됩니다.
    2. 
            
  2. 클레임 표에서 exp(만료), iat(발급), nbf(유효 시작)를 한국 시간으로 확인합니다.
    3. 
            
  3. 서명을 확인하려면 키를 넣고 서명 검증을 누릅니다. HS 계열은 공유 비밀키, RS·PS·ES 계열은 공개키(PEM 또는 JWK)를 넣습니다.
    4. 
          

          
JWT 구조

          
JWT는 점(.)으로 구분된 세 부분으로 이루어집니다. Header에는 서명 알고리즘(alg)과 토큰 타입이, Payload에는 사용자 ID·권한·만료 시각 같은 클레임이, Signature에는 앞의 두 부분을 키로 서명한 값이 들어갑니다. 앞의 두 부분은 Base64URL로 인코딩만 되어 있어서 암호화되지 않습니다.

          
주요 등록 클레임

          
    
            
  • iss 발급자 · sub 주체(사용자) · aud 대상
    • 
            
  • exp 만료 시각 · nbf 이 시각 전에는 무효 · iat 발급 시각 (모두 Unix 초)
    • 
            
  • jti 토큰 고유 ID (재사용 방지)
    • 
          

          
자주 묻는 질문

          

            
토큰을 붙여넣어도 안전한가요?
토큰과 키는 이 페이지 밖으로 나가지 않습니다. 디코딩과 서명 검증은 브라우저 내장 Web Crypto API로 처리합니다. 그래도 운영 환경 토큰은 만료된 것이나 테스트용을 쓰는 편이 좋습니다.

            
어떤 알고리즘을 검증할 수 있나요?
HS256/384/512(공유 비밀키), RS256/384/512와 PS256/384/512(RSA 공개키), ES256/384/512(EC 공개키)를 지원합니다. 공개키는 PEM(-----BEGIN PUBLIC KEY-----) 또는 JWK(JSON) 형식으로 넣으면 됩니다.

            
디코딩이 된다고 토큰이 유효한 건가요?
아니요. JWT의 Header와 Payload는 단순 Base64URL 인코딩이라 누구나 읽을 수 있습니다. 위조 여부는 서명 검증을 통과해야 알 수 있습니다.
